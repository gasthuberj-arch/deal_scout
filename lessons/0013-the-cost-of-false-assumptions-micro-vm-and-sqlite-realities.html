Systems Architecture • Lesson 0013

The Cost of False Assumptions: Micro-VM & SQLite Realities

Dissecting the production bets that broke under constraint, and the physical principles that replace them.

Tied to Your Mission

In software architecture, we often inherit default configurations and mental models built for unconstrained multi-core servers. When deployed to a realistic, highly cost-effective environment—like a 512 MB RAM / 1 shared vCPU container with an exclusive NVMe block storage volume on Fly.io—these assumptions quietly break. This lesson examines the specific architectural bets that turned out wrong in DealScout, extracting core principles that safeguard resource-constrained production systems.

1. The Multiplicative Cache Sizing Illusion

The Bet: "We configured the database adapter with default settings, so memory usage is modest and safe."

In ecto_sqlite3, the default configuration sets cache_size: -64000. A negative integer in SQLite denotes cache size in kibibytes, meaning 64,000 KiB (62.5 MiB). When paired with a default connection pool of pool_size: 5, a hidden multiplication occurs:

$$\text{Max Pager Cache Footprint} = \text{pool\_size} \times |\text{cache\_size}| = 5 \times 62.5\,\text{MiB} = \mathbf{312.5\,\text{MiB}}$$

Each Ecto connection maintains its own independent SQLite pager cache. On a 512 MB micro-VM, BEAM process heaps, code tables, and OS buffers leave approximately 222 MB of RAM free at idle. Under concurrent traffic across disparate tables (feed ingestion, analytics aggregations, deal listings), the 5 connections expand their page caches to claim 312.5 MB. Total container memory hits the Linux cgroups v2 memory.max ceiling, triggering an instant, non-negotiable OOM kill (signal 9).

The Enduring Principle: Connection pools multiply memory allocations. Every buffer, pager, and socket size must be calculated as $N_{\text{connections}} \times \text{Buffer Size} < \text{Available Headroom}$. Lowering cache_size to -8000 (8 MiB per connection = 40 MiB total) comfortably caches the working set while leaving over 180 MB of breathing room for BEAM heaps.

2. The "Deferred" Concurrency Deadlock Trap

The Bet: "SQLite WAL mode allows concurrent readers and writers, and transactions will serialize cleanly with busy timeouts."

By default, ecto_sqlite3 executes transactions in :deferred mode (BEGIN DEFERRED). Under SQLite's locking rules:

  1. BEGIN DEFERRED acquires no lock.
  2. The first SELECT acquires a SHARED (read) lock.
  3. The subsequent INSERT or UPDATE attempts to upgrade the SHARED lock to a RESERVED (write) lock.
Process A: BEGIN DEFERRED ──► SELECT (SHARED) ──► Attempt UPDATE (Needs RESERVED) ──┐ DEADLOCK!
                                                                                    ├──► SQLITE_BUSY
Process B: BEGIN DEFERRED ──► SELECT (SHARED) ──► Attempt UPDATE (Needs RESERVED) ──┘ (Bypasses busy_timeout!)

When two concurrent processes read before writing, both hold SHARED locks. Neither can upgrade to RESERVED because the other process's read lock blocks it. SQLite identifies this circular wait immediately and aborts with (Exqlite.Error) database is locked. SQLite's busy handler is completely bypassed because waiting cannot break the deadlock.

The Enduring Principle: Declare mutation intent at the root. Setting default_transaction_mode: :immediate forces every transaction to issue BEGIN IMMEDIATE. This acquires the RESERVED lock at inception before executing reads. Concurrent writers queue politely in the busy handler rather than deadlocking mid-transaction.

3. The Ghost Scaler: Reverse Proxy Limits vs. Physical Invariants

The Bet: "Setting high proxy concurrency limits (800 soft / 1,000 hard) lets Fly absorb traffic spikes and autoscale."

This bet conflated stateless application assumptions with stateful single-volume realities:

  • Exclusive Block Devices: Fly Volumes are ext4-formatted NVMe block devices attached to a single physical host. A volume cannot be attached to more than one machine at a time. The proxy's soft_limit triggers autoscaling to spawn new machines, but Fly cannot boot a second machine on the same volume.
  • BEAM Process Overhead: LiveView maintains stateful WebSockets. 800 connections mean 800 channel processes, 800 socket buffers, and active DOM diff tracking. On a 1 shared vCPU core, scheduling delays cause WebSocket heartbeat timeouts, triggering massive reconnection stampedes.

The Enduring Principle: Admission control must match physical capacity, not theoretical elasticity. Configuring realistic limits (e.g., soft_limit = 200, hard_limit = 300) forces the edge proxy to reject or queue excess requests with 503 Service Unavailable before the single node experiences scheduler collapse.

4. The Headless OS Signal Blind Spot

The Bet: "Container shutdown cleanly drains WebSockets and checkpoints the database."

Fly.io defaults to sending SIGINT when stopping a container. In Erlang/OTP releases, SIGINT is mapped to the runtime's interactive BREAK handler:

app[784ee035fd6338] INFO Sending signal SIGINT to main child process w/ PID 643
app[784ee035fd6338] BREAK: (a)bort (A)bort with dump (c)ontinue (p)roc info (i)nfo
app[784ee035fd6338]        (l)oaded (v)ersion (k)ill (D)b-tables (d)istribution

Because the container lacks an interactive keyboard terminal, BEAM hangs waiting for input. After the stop timeout expires, the orchestrator forcefully sends SIGKILL (kill -9). As a result:

  • WebSockets drop abruptly without sending close frames (1001 Going Away).
  • SQLite never runs PRAGMA wal_checkpoint(TRUNCATE), leaving uncommitted WAL frames on disk.
  • In-flight background ingestion tasks terminate ungracefully.

The Enduring Principle: Align process boundary protocols explicitly. Setting kill_signal = "SIGTERM" in fly.toml invokes init:stop/0 in OTP, triggering an orderly shutdown of Endpoint connections, background GenServers, and database connections.

5. Summary: False Bets vs. Physical Realities

The False Bet The Physical Reality The Enduring Principle
Default cache sizes are modest $5 \times 62.5\,\text{MiB} = 312.5\,\text{MiB}$, exceeding the 222 MB available RAM and triggering OOM. Pool state multiplies linearly; bound every pool allocation against total free RAM.
Transactions serialize via timeout Concurrent DEFERRED transactions deadlock when upgrading SHARED to RESERVED. Declare write intent up front using BEGIN IMMEDIATE to serialize writers cleanly.
High proxy limits enable autoscaling Single exclusive volumes cannot autoscale; 800 WebSockets choke 1 shared vCPU. Configure edge admission control to match the physical ceiling of the single node.
Containers shut down gracefully Fly sends SIGINT, freezing BEAM at an interactive prompt until killed with SIGKILL. Explicitly configure SIGTERM to invoke OTP application drain and SQLite checkpoints.
Snapshots to /tmp are safe backups /tmp resides in RAM or container overlayfs; writing 100 MB spikes memory into OOM. Stream WAL mutations continuously out-of-band (e.g. Litestream to S3) with zero RAM bloat.
