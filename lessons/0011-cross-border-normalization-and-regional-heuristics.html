Domain Engineering • Lesson 0011

Cross-Border Normalization & Regional Heuristics

Taxonomy classification, merchant origin heuristics, and foreign hardware layout detection.

Tied to Your Mission

European deal aggregators frequently source deals from foreign Amazon branches (Amazon.es, Amazon.fr, Amazon.it). While savings on graphics cards or headphones translate seamlessly, laptops and keyboards carry physical layout traps (French AZERTY, Spanish QWERTY). This lesson explores how DealScout.Deals.CrossBorder enriches deals at ingestion.

1. The Real-World Cross-Border Trap

A German or Austrian user spotting a €900 MacBook on Amazon Spain might jump on the purchase—only to discover upon delivery that the physical keyboard has Spanish punctuation keys, an inverted enter key, or an AZERTY layout. Worse, return shipping across borders often incurs non-refundable postage.

A smart aggregator must not treat deals as generic text; it must enrich each deal with geographic origin and physical compatibility metadata.

2. Layer 1: Merchant Domain & Host Heuristics

In DealScout.Deals.CrossBorder.detect_country/1, the origin country is resolved using a cascaded heuristic:

Deal URL Hostname Analysis:
amazon.fr, dealabs.com, fnac.com    ───► %{code: "FR", flag: "🇫🇷", name: "France"}
amazon.es, chollometro.com          ───► %{code: "ES", flag: "🇪🇸", name: "Spain"}
amazon.it                           ───► %{code: "IT", flag: "🇮🇹", name: "Italy"}
preisjaeger.at, amazon.at           ───► %{code: "AT", flag: "🇦🇹", name: "Austria"}
amazon.co.uk                        ───► %{code: "UK", flag: "🇬🇧", name: "UK"}

If the URL is a redirection affiliate link, fallback regular expressions scan the title and deal body for text signatures (e.g. [amazon.es], amazon spanien, dealabs).

3. Layer 2: Hardware Taxonomy & Layout Warnings

Not every product from France or Spain requires a keyboard warning. Audio equipment, monitors, and RAM work identically regardless of origin country. The heuristic must only trigger when hardware with physical keys is detected:

  1. Hardware Keyword Match: 
    @keyboard_hardware_pattern ~r/\b(laptop|notebook|macbook|thinkpad|zenbook|ideapad|tastatur|keyboard|chromebook)\b/iu
  2. Explicit Layout Tokens in Text: If the deal text explicitly mentions azerty, qwerty, ansi, or französisches layout, an immediate warning is generated regardless of the merchant store.
  3. Implicit Regional Defaults: If hardware keywords match and the country is France (FR), a warning flag for AZERTY is attached. If Spain (ES), QWERTY-ES is attached.

4. Architectural Pattern: Ingestion-Time Precomputation

Why Precompute in Ingestion?

Running multi-step regex cascades across titles and URLs on every user page load or LiveView stream render destroys UI responsiveness. DealScout runs CrossBorder.enrich/1 once during ingestion and persists country and keyboard_warning directly onto the %Deal{} database schema. Reads remain pure, zero-cost column accesses.
