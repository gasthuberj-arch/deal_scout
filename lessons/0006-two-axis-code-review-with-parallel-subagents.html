Two-Axis Code Review with Parallel Sub-Agents

How to evaluate code along Standards and Spec simultaneously without cognitive masking.

Applied to Real Workflows

When you or a peer agent writes code—like the PWA and Web Push feature currently taking shape in DealScout—how do you know it's ready to merge? This lesson introduces the multi-agent review pattern from code-review.

1. The Problem with Monolithic Reviews

Traditional human code review (and naive single-prompt AI review) suffers from a major blind spot: cognitive masking. Reviewers get dragged into styling debates, missing that the PR failed to implement an essential requirement. Or conversely, reviewers verify that the feature works, completely ignoring that the code introduced severe architectural rot (Middle Men, Feature Envy, or broken boundaries).

2. The Two Orthogonal Axes

A pull request can pass one axis while utterly failing the other:

  • Standards Pass, Spec Fail: Beautifully formatted, idiomatic Elixir that implements the wrong behavior or solves the wrong problem.
  • Spec Pass, Standards Fail: The feature works for the user, but violates repository architecture rules (`AGENTS.md`) and introduces technical debt.

3. The Parallel Sub-Agent Architecture

Rather than asking one agent to juggle both concerns, the review dispatches two parallel sub-agents against git diff <base>...HEAD:

                     ┌─────────────────────────────┐
                     │   git diff <base>...HEAD    │
                     └──────────────┬──────────────┘
                                    │
               ┌────────────────────┴────────────────────┐
               ▼                                         ▼
   ┌───────────────────────┐                 ┌───────────────────────┐
   │  Standards Sub-Agent  │                 │    Spec Sub-Agent     │
   │  - AGENTS.md rules    │                 │  - Issue requirements │
   │  - Fowler smells      │                 │  - Scope creep check  │
   │  - Architecture rules │                 │  - Missing edges      │
   └───────────┬───────────┘                 └───────────┬───────────┘
               │                                         │
               └────────────────────┬────────────────────┘
                                    ▼
                     ┌─────────────────────────────┐
                     │   Side-by-Side Synthesis    │
                     │   (No cross-axis reranking) │
                     └─────────────────────────────┘

By keeping the reports side-by-side without merging them into a single score, neither axis can hide behind the other.
