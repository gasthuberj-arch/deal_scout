Architecture • Lesson 0001

Deep Modules & The Leverage Test

How to deliver maximum behavior behind minimum surface area in DealScout.

Tied to Your Mission

In MISSION.md, our target is designing robust, high-leverage modules in DealScout that resist rot. This lesson equips you with the vocabulary and mental model to spot shallow wrappers and design deep, durable interfaces.

1. The Problem: Shallow Sprawl

In web codebases like DealScout, code frequently rots not from too little abstraction, but from shallow abstraction. Developers create layers of single-method modules, wrappers around wrappers, and pass-through delegates that do almost nothing except re-expose the underlying library's complexity under a different name.

A shallow module forces callers to learn a complex interface (parameters, configuration, error conditions) while providing almost no behavior in return.

2. Deep vs. Shallow Defined

Depth is leverage at the interface: the amount of behavior a caller or test can exercise per unit of interface they have to learn.

A deep module has a small, simple interface that conceals substantial internal complexity behind it:

DEEP MODULE (High Leverage)
┌────────────────────────────────────────────────────────┐
│  DealScout.Deals.ingest_feed(source, url)              │ ← Tiny surface
├────────────────────────────────────────────────────────┤
│  - Downloads HTTP stream via Req with backoff          │
│  - Parses XML/JSON vendor formats                      │ ← Deep implementation
│  - Normalizes currencies and timestamps                │
│  - Deduplicates against existing database deals        │
│  - Emits telemetry and notifies LiveView subscribers   │
└────────────────────────────────────────────────────────┘

SHALLOW MODULE (Low Leverage / Wrapper)
┌────────────────────────────────────────────────────────┐
│  DealScout.HttpWrapper.get(url, headers, timeout, ...) │ ← Same size as Req
├────────────────────────────────────────────────────────┤
│  Req.get!(url, headers: headers, receive_timeout: ...) │ ← Zero hidden work
└────────────────────────────────────────────────────────┘

Notice the difference: HttpWrapper gives callers zero leverage. If you delete HttpWrapper, callers just call Req.get/2 directly with zero lost behavior. But deleting DealScout.Deals.ingest_feed/2 would require scattering five distinct subsystems across every caller.

3. The Deletion Test

Whenever you are evaluating whether an Elixir module in DealScout is earning its keep, run The Deletion Test:

  • Imagine deleting the module entirely.
  • If its complexity vanishes (it was just delegating or re-formatting arguments), it was a shallow pass-through that shouldn't exist.
  • If its complexity scatters across ten caller sites, it was a deep module earning its keep.
