Diagnosing Bugs & Feedback Loops

The scientific 6-phase discipline for isolating and eliminating non-trivial defects.

← Back to Lesson 0005: Root-Cause Diagnosis
Core Creed: Building the feedback loop IS the skill. Everything else is mechanical. If you have a tight, red-capable pass/fail signal, you will find the bug.

The Six Phases of Scientific Diagnosis

Phase 1: Build the Feedback Loop

Construct a single, repeatable command (test, curl, script, or trace replay) that drives the exact code path and asserts the user's specific symptom. Never hypothesize before this loop exists.

  • Red-capable: Fails on this exact defect.
  • Deterministic: Consistent result every run (or pinned high repro rate).
  • Fast: Takes seconds, not minutes.
Phase 2: Reproduce & Minimize

Shrink the scenario to the smallest input that still goes red. Remove configuration, callers, and data one by one. Done when every remaining element is load-bearing (removing any one makes it go green).

Phase 3: Hypothesize (3–5 Ranked Predictions)

Generate 3–5 falsifiable hypotheses before testing. Avoid anchoring on the first thought. Format: "If X is the cause, then changing Y makes it vanish / Z makes it worse."

Phase 4: Targeted Instrumentation

Change one variable at a time. Tag every log with a unique prefix (e.g. [DEBUG-a7b2]) for zero-risk cleanup. Prefer debuggers and targeted boundary probes over "logging everything".

Phase 5: Fix & Regression Test

Write the regression test at the correct public seam before applying the fix. Watch it fail, apply the fix, and watch it turn green.

Phase 6: Cleanup

Grep and remove all tagged debug logs, delete throwaway harnesses, and ensure the original Phase 1 loop passes completely.
