Cross-Border Normalization Reference

Quick reference for origin detection, hardware tagging, and keyboard layout warnings.

Core Normalization Primitives

Host Domain Country Mapping

Extract URI host from deal URL. Map recognized European Amazon/community domains directly to country code, flag emoji, and localized name.

URI.parse(url).host -> "amazon.fr" -> FR
Title & Text Fallback Heuristic

When deal URLs use affiliate link shorteners or cloaked redirects, inspect title and clean text for localized merchant tags like [amazon.es] or dealabs.

Regex.run(~r/\[amazon\.es\]|dealabs/iu, text)
Hardware Taxonomy Gating

Restrict keyboard layout warnings strictly to products matching keyboard/laptop hardware keywords to prevent false positives on audio or monitors.

~r/\b(laptop|notebook|macbook|tastatur)\b/iu
Explicit Layout Token Detection

Scan title and body for explicit layout markers (azerty, qwerty, ansi, us-layout). When found, issue an immediate warning regardless of origin country.

~r/\b(azerty|qwerty|ansi|us-layout)\b/iu
Implicit Regional Layout Defaults

Hardware sourced from France defaults to AZERTY warnings. Hardware sourced from Spain defaults to QWERTY-ES warnings. Protects unaware domestic buyers.

country_code == "FR" and is_hardware? -> "AZERTY"
Write-Time Precomputation

Execute enrichment during deal ingestion pipeline and persist country and keyboard_warning onto %Deal{} to eliminate read-path regex compute overhead.

%{deal | country: c, keyboard_warning: kw}

Ingestion Audit Checklist

  • [ ] Taxonomy: Does non-keyboard hardware bypass physical layout warning rules?
  • [ ] Fallback: Can deals with redirect affiliate domains still resolve origin countries?
  • [ ] Persistence: Are enriched flags stored in DB columns rather than computed in LiveView renders?
  • [ ] Null-Safe: Does the enrichment pipeline handle nil URLs and nil titles gracefully?
