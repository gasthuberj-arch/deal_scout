Core Migration Verification Patterns

N-1 State Simulation

Migrate a temporary test database up to the second-to-last migration version (N-1) to replicate exact pre-deploy production schema and triggers.

Ecto.Migrator.run(repo, path, :up, to: prior_version)
Recursive CTE Fast Seeding

Seed 1,000 realistic rows in a single SQL statement (<20ms) using WITH RECURSIVE cnt(x) so the test suite stays fast.

WITH RECURSIVE cnt(x) AS (SELECT 1 UNION ALL ...)
WAL Baseline Truncation

Checkpoint and truncate the SQLite write-ahead log to 0 bytes right before running migration N to isolate its exact write footprint.

PRAGMA wal_checkpoint(TRUNCATE);
Runtime & WAL Budget Gate

Measure both wall-clock execution time and resulting .db-wal file size after migration N completes.

assert duration_ms < 750 and wal_bytes < 12_582_912
Immutability of Historical Migrations

Never modify migrations that have already executed in production; doing so causes silent schema drift between fresh test DBs and prod.

Write a new migration instead of editing old ones
Avoiding AST Regex Coupling

Static regexes on migration files miss triggers created in earlier migrations and break on valid SQL formatting variations.

Test database outcomes, not SQL string spelling

Migration Gate Checklist

  • [ ] Historical Immutability: Did `git diff` leave all previously deployed migration files untouched?
  • [ ] Seeded Benchmark: Does `test/deal_scout/repo_migration_test.exs` pass the 1,000-row N-1 → N runtime (<750ms) and WAL (<12MB) budgets?
  • [ ] Rollback Verification: Does the full `up` → `down` → `up` cycle in `RepoMigrationTest` succeed cleanly?
