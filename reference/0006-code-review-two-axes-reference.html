Review Reference 0006

Two-Axis Code Review

Separating Standards and Spec into parallel sub-agents to prevent masking.

← Back to Lesson 0006: Two-Axis Code Review
The Core Insight: A change can pass one axis and fail the other. Code can follow every standard perfectly while implementing the wrong feature (Standards pass, Spec fail). Or it can do exactly what was asked while breaking architecture rules (Spec pass, Standards fail). Reporting them separately stops one axis from masking the other.

The Two Review Axes

Axis 1: Standards
Does the code follow repo guidelines?
  • Documented repo rules (e.g. AGENTS.md, Phoenix v1.8 conventions).
  • Fowler code smells (Middle Man, Feature Envy, Speculative Generality).
  • Repo standards always override general baselines.
  • Focus: Code hygiene, maintainability, architectural health.
Axis 2: Spec
Does the code match what was asked for?
  • Missing or partially implemented requirements.
  • Scope creep (unrequested behavior or speculative knobs).
  • Incorrect interpretations of domain requirements.
  • Focus: Fidelity to intent and user value.

Why Use Parallel Sub-Agents?

  • Context Independence: A single agent reviewing a PR easily suffers from confirmation bias or gets distracted arguing about variable names while missing that a core requirement was omitted.
  • Speed: Spawning two lightweight sub-agents runs both analyses concurrently against git diff <base>...HEAD.
  • Side-by-Side Aggregation: Findings are presented side-by-side without reranking across axes.
