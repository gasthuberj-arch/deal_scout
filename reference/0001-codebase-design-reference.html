Deep Modules & Seams Reference

Canonical vocabulary and principles for high-leverage module design.

Core Architecture Vocabulary

Module

Anything with an interface and an implementation. Deliberately scale-agnostic: a single function, an Elixir context, an OTP process, or a subsystem.

Avoid: component, unit, service
Interface

Everything a caller must know to use the module correctly: type signatures, invariants, ordering constraints, error modes, configuration, and runtime traits.

Avoid: API, signature (too narrow)
Implementation

The code body inside the module. What callers do not see. Distinct from an adapter: adapter describes the role at a seam; implementation is what is inside.

Avoid confusing role with body
Depth

Leverage at the interface. The amount of behavior a caller or test can exercise per unit of interface complexity they must learn. Deep = small surface, rich logic.

Avoid: measuring lines of code
Seam (Feathers)

A place where you can alter behavior without editing in that place; the exact location where a module's interface lives.

Avoid: boundary (overloaded with DDD)
Adapter

A concrete thing that satisfies an interface at a seam. Describes role (e.g. Postgres repo vs in-memory fake), not internal code size.

Avoid: introducing with 1 implementation
Leverage

What callers get from depth: massive capability unlocked with minimal cognitive surface. One implementation pays back across N call sites and M tests.

Locality

What maintainers get from depth: change, bugs, and invariants concentrate in one place rather than leaking across callers. Fix once, fixed everywhere.

Critical Heuristics

  • The Deletion Test: If you delete the module and complexity simply vanishes, it was a pass-through. If complexity disperses into 10 callers, it was earning its keep.
  • The Interface is the Test Surface: Callers and tests cross the same seam. If you need to test private internals past the interface, the module shape is wrong.
  • Seam Discipline: One adapter = a hypothetical seam (unjustified indirection). Two adapters (e.g., Prod + In-Memory Test) = a real seam.
