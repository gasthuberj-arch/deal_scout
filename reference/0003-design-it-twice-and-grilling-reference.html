Pattern 1: Design It Twice (Ousterhout)

Your first interface idea is rarely the best. Before writing code, explore 3+ radically different shapes:

Approach A: Minimal Surface
1–3 entry points max.

Maximizes leverage per call. Default configuration, hidden complexity, opinionated defaults.

Approach B: Maximum Flexibility
Configurable & Extensible.

Supports custom pipelines, plugins, and pluggable strategies behind the interface.

Approach C: Common-Case First
Zero-friction default call.

Optimizes ergonomics for 90% of callers, tucking advanced options into optional keyword lists.

Approach D: Ports & Adapters
Seam-first decoupling.

Decouples business logic from external transports or database representations.

Pattern 2: Grilling (Decision Tree Frontier)

Systematically stress-test an architecture plan before implementation by interrogating the decision tree:

Rule 1: The Frontier
Ask only settled prerequisites.

The frontier contains decisions that can be answered right now without guessing unsettled upstream questions.

Rule 2: Facts vs. Decisions
Agents find facts; users make decisions.

Never ask the user for facts obtainable from the filesystem, codebase, or tests. Dispatch tool calls or sub-agents to find facts; put only decisions to the user.

Rule 3: Recommendation Phrasing
Provide a clear recommendation.

Word questions so that replying "yes" accepts the recommended answer. The user directs; the system evaluates.

Rule 4: Stop Condition
Empty Frontier.

The grilling session concludes only when every branch of the design tree has been visited and zero silent assumptions remain.
