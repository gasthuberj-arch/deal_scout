Compute Guards & ReDoS Defense

Quick reference for execution budgets, circuit breakers, AST limiting, and slow logging.

Core Compute Guard Primitives

Microsecond Budgeting

Measure execution time using System.monotonic_time(:microsecond). Divide elapsed microseconds by batch deal count to calculate fair normalized duration per item.

div(elapsed_us, max(length(deals), 1))
Auto-Pause Circuit Breaker

When normalized duration exceeds the safety threshold (default 30ms/deal), immediately disable the offending rule in the database and mark the index dirty.

apply_auto_pause(rule, duration, budget)
NDJSON Slow Eval Logging

Append execution metadata to a structured append-only NDJSON log file when total batch duration exceeds 5,000µs for offline diagnosis and performance audits.

File.write(path, json <> "\n", [:append])
AST Grammar Bounding

Never permit unconstrained raw regular expressions. Parse queries into an AST with strictly bounded token counts and maximum recursion depth.

DealScout.KeywordEngine.Query.parse/1
Linear Aho-Corasick Scans

Extract all search literals into a deterministic finite automaton (:binary.compile_pattern). Guarantees O(text length) scanning regardless of query quantity.

:binary.matches(text, compiled_pattern)
Live User Broadcast

When an alert is paused by the compute guard, emit an event over Phoenix.PubSub so the user's dashboard displays an explanatory notification immediately.

broadcast({:rule_auto_paused, rule, reason})

Audit Checklist: Query Safety

  • [ ] Grammar: Does the parser reject nested repetition patterns like (a+)+?
  • [ ] Isolation: Is user query execution wrapped inside ComputeGuard.run/4?
  • [ ] Thresholds: Are per-deal budgets (30_000µs) and slow log thresholds (5_000µs) configured?
  • [ ] Index Invalidation: Does auto-pausing a rule immediately call KeywordEngine.mark_dirty()?
