# Authentication & Routing Guidelines

Reference for routing, authentication plugs, and live sessions generated by `phx.gen.auth`.

---

## 1. Current Scope Convention

- `phx.gen.auth` assigns `@current_scope` (containing `@current_scope.user`), **never** `@current_user`.
- In LiveView templates, always reference `@current_scope.user`.
- Always pass `current_scope` as the first argument to domain context modules.
- Scope all database queries by `current_scope.user` to ensure user tenancy isolation.

---

## 2. Router Scopes and Sessions

The router defines three primary scopes and pipelines:

### Authenticated LiveViews (`:require_authenticated_user`)
All LiveViews that require a logged-in user must sit inside the existing `:require_authenticated_user` session:

```elixir
scope "/", DealScoutWeb do
  pipe_through [:browser, :require_authenticated_user]

  live_session :require_authenticated_user,
    on_mount: [{DealScoutWeb.UserAuth, :require_authenticated}] do
    live "/alerts", AlertRuleLive.Index, :index
    live "/alerts/new", AlertRuleLive.Index, :new
    live "/users/settings", UserLive.Settings, :edit
  end
end
```

### Public / Optional Auth LiveViews (`:current_user`)
LiveViews that work both with and without authentication must sit inside the `:current_user` session:

```elixir
scope "/", DealScoutWeb do
  pipe_through [:browser]

  live_session :current_user,
    on_mount: [{DealScoutWeb.UserAuth, :mount_current_scope}] do
    live "/", DealLive.Index, :index
  end
end
```

### Unauthenticated Only (`redirect_if_user_is_authenticated`)
Registration and log-in pages that should redirect already logged-in users:

```elixir
scope "/", DealScoutWeb do
  pipe_through [:browser, :redirect_if_user_is_authenticated]

  live_session :redirect_if_user_is_authenticated,
    on_mount: [{DealScoutWeb.UserAuth, :redirect_if_user_is_authenticated}] do
    live "/users/register", UserLive.Registration, :new
    live "/users/log-in", UserLive.Login, :new
  end
end
```

---

## 3. Key Invariants

- **Single live_session name**: Never define a `live_session` with the same name more than once in `router.ex`. Group all routes sharing a session inside one block.
- **Missing current_scope error**: If a template complains that `current_scope` is missing, verify that the route is inside a live session with `:mount_current_scope` or `:require_authenticated` and that `@current_scope` is passed to `<Layouts.app>`.
- **Navigation boundaries**: `<.link navigate={...}>` cannot cross between different `live_session` blocks over the same WebSocket. Use standard HTTP links (`<.link href={...}>`) when crossing session boundaries.
